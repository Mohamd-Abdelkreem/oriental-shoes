# Oriental Shoes front-end migration audit

## Scope and source inventory

Read-only source: `C:\Users\moham\OneDrive\Desktop\factory`. Destination: `apps/web` in this repository. The source has 92 entries in `scripts/route-manifest.json`, 111 reference PNGs in `screens`, a root page, a catch-all route, and six additional physical page files. The catch-all uses `components/mvp-app.tsx` to dispatch role workspaces. Its root `/` redirects to `/prototype-preview`. The source manifest includes sample data URLs, so multiple entries share one dynamic destination route pattern. The source's `components/ui` kit is not used by the reached workspace UI and was not copied.

The table records every manifest entry. “Protected prototype” means a real destination session protects a screen whose manufacturing data and actions remain browser-local mock behavior. “Real auth” means the destination's existing API-backed form is authoritative. “Development preview” is unavailable in production. “Real account” is a deliberate consolidation onto existing API-backed account controls.

- Added `lucide-react` to `@template/web` because the reached source screens use Lucide icons; the pnpm lockfile was updated.
- Loaded Cairo through `next/font/google` in the root layout and removed the local TTF copies. Added a small Oriental Shoes SVG favicon to `apps/web/public/favicon.svg`.
- Reused the destination's Next.js 16, React, Tailwind, form, auth, and API stack. No alternate UI framework or state library was added. Source screenshots were used only for QA, never as runtime assets.

## Authentication and prototype boundary

Real login, registration, email verification, password recovery, profile updates, password changes, session refresh, and signout continue to use the destination API and session hooks. The Oriental workspace displays the real account name and signs out through the real mutation. The role account cards display the real `ADMIN` or `USER` account role; department names in navigation label prototype work areas, not permissions. All manufacturing routes use `ProtectedRoute`. Print routes additionally require real `ADMIN`. The destination contract exposes only `ADMIN` and `USER`; department authorization requires separate backend and contract work. Orders, customers, employees, production progress, dialogs, and reports remain browser-local prototype data. Mock auth/role-preview pages render not-found UI in production. Next.js may return HTTP 200 for a streamed `notFound()` response; the prototype content is not rendered and the response includes `noindex` metadata.

The source print view also checks its mock role state. Removing that check was rejected by automatic approval review because it could expose customer and price data to any authenticated user. It remains alongside the real ADMIN route guard; real sales and approval print permissions therefore cannot match the mock source workflow until department roles exist.
