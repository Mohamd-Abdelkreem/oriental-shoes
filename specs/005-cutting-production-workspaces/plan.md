## Summary

Connect the reached cutting and production workspaces to the same authoritative submitted pieces used by P03/P04. Preserve both order/task routes, grouped/flat tables, dialogs, Arabic/RTL/Cairo and factory-safe manufacturing specifications. All seven types follow cutting → production → quality. Colleagues may continue work while retaining the original starter and each actual subsequent actor.

A single manufacturing command accepts an exact selected set, including selections across orders. Current actor authority and every selected piece/order version are checked inside one transaction; either the entire selection commits with retained receipt/movement/history or none of it does. Work visits distinguish initial entry, correction reentry, original start, continuation and completion. P04 owns issue reporting/decisions and remains its command/result authority; P05 binds its controls and maintains visit consistency within the same P04 transaction. Normal P05 transfer stops at quality incoming.

The current foundation has real submitted pieces, P04 issue/approval records and single-order command ledgers. Manufacturing screens still use local MVP mutations, fixed workers, quantity-segment fallbacks and incompatible finance-bearing view types. The design adds a bounded manufacturing module, visit/command records and safe frontend view models; it does not build an assignment platform, copy authentication, replace transport, or introduce a general workflow framework.

## Contracts, Authority and Failure Design

[contracts/manufacturing.md](contracts/manufacturing.md) is the sole wire/schema/error/DTO owner. [data-model.md](data-model.md) owns fields, constraints, witnesses and migration/existing-data rules. [backend-design.md](backend-design.md) owns ordered write/read enforcement; [frontend-design.md](frontend-design.md) owns query/cache/form/late-response behavior. Do not copy a competing schema or transaction algorithm into TASKS.

The existing API prefix is configurable via `API_PREFIX`, default `/api/v1`. Contract paths are relative to that prefix. The existing centralized browser client supplies it; no adapter prepends the prefix twice. New commands use the current credential/CSRF protocol and strict command shape. Department URL selection describes intended context and is independently authorized against current server identity.

No successful work response means only completion without transfer, a skipped invalid selected piece, a locally mutated screen or a partial cross-order commit. A known validation/authority/state rejection leaves the whole selection unchanged. A network/contract/transport failure can leave the outcome unknown: observe original intent, rather than interpreting it as a rejected write. A receipt is an immutable historical outcome, not a replacement for current safe detail or current permission.

P04 report routing/body/receipt remain intact; its lifecycle collaboration is an internal transactional extension, not a new manufacturing issue decision. New work activity must also appear as safe per-order summaries in existing sales/approval tracking/activity without leaking raw facts to factory readers. Producer/consumer changes ship together in one later implementation; independent old web consumers cannot parse the newly added activity variant and require coordinated rollout.
