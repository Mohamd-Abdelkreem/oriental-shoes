#### Defect 1 (product, owned by T026) — the guest guard discarded every post-login navigation

- **Symptom**: with the harness running, a real credential login returned `200` from
  `POST /api/v1/auth/login` and `200` from `GET /api/v1/users/me`, yet the page stayed on
  `/auth/login` showing the session loader instead of reaching the workspace.
- **Root cause**: `apps/web/src/components/auth/guest-only-route.tsx` compared the **live**
  credential-lifecycle epoch against a **render-time snapshot** of the same module value inside
  the redirect effect. Under the real browser the render-time read could lag the live value by
  one render phase, so `getAuthSessionEpoch() !== currentEpoch` was always true for a
  credential that had just been accepted and the sole replacement was discarded. The unit suite
  never observed it because it mocks the transport module.
- **Fix**: the epoch is now held in component state and adjusted during render, so the committed
  render always carries the current epoch, and the effect additionally rechecks the epoch
  **live before and after** its remaining checks, so the replacement can never cross a
  credential-lifecycle boundary.
- **Regression coverage**: `apps/web/src/components/auth/routes.test.tsx` now pins the real
  ordering — the lifecycle advances, the credential is accepted and the account becomes
  current — and asserts the single replacement. The file also restores the shared transport
