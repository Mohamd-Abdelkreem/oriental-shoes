## Contracts, Authority and Failure Design

[Administration contract](contracts/administration.md) is the single proposed wire owner: exact exports, normalized filter/option shapes, method/path/status/middleware, safe read/event/command DTOs, text/money/date/null semantics, context echoes, body/output limits and error codes. B01/B06 define current actor admission and transaction/lock/replay order; D02 defines database enforcement. Do not copy a second schema into DTOs/forms.

- Reuse existing business identity/current authority and require eligible ADMIN at every admin read/write, including replay/observe. Browser hints are presentation only. Actor share lock precedes command/root/piece locks; deterministic root/piece order preserves existing competing-domain serialization.
- Commands are one-order reviewed intents under original UUID/version/canonical hash; replay returns historical committed receipt, followed by fresh current reads. Changed intent/invalid/stale state rejects the whole action. There is no remote/spending effect, no automatic mutation retry and no fake success after timeout.
- Original submitted contacts/prices/paid/history remain. Effective contact projections are allowlisted per existing role; full admin before/after facts never become factory/warehouse output. Safe operational event variants omit private correction values/free text.
- Lists/counts/report sections use server predicates and a shared read transaction, stable sort and context binding. Complete-report guards fail visibly with no partial DTO. Print later is a new time-stamped observation; once loaded, it does not mutate during physical printing.
- Expected validation/denial/conflict/unknown/unexpected errors use accepted English-described Arabic UI meanings, field associations and safe recovery. Dirty input and confirmed receipts survive recoverable failures; late old-context publication is rejected.
